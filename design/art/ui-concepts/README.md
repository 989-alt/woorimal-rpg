# UI 시안: 말빛 한울 화면 틀 다시 그리기

> 상태: **선생님 승인 2026-11-04**. 승인된 시안대로 아트 바이블 3·4·7·8절을 고쳤고(아래 "아트 바이블과 다른 점"),
> 구현은 `docs/superpowers/plans/2026-11-04-ui-overhaul-tutorial.md`를 따른다.

선생님이 "어느 게임사의 메인화면과 플레이 ui가 이 따위야"라고 지적했다. 지금 화면은 마을 그림 위에 웹 양식 상자를 띄운 타이틀, 베이지 종이 위에 카드처럼 놓인 맵, 둥근 사각형 HUD와 대사 상자로 되어 있다. 이 시안은 **그림과 내용은 그대로 두고 화면 틀(UI)만** 다시 그렸다. 한국 2D 판타지 RPG 갈래의 말투(조각한 나무 틀, 놋쇠 테두리, 보석 징, 윤나는 입체 버튼, 빛나는 제목 로고, 키 배지가 달린 아이콘 버튼, 초상 메달, 이름 리본, 두루마리 할 일 표)를 빌렸다. 특정 게임의 UI·로고·이름·배치는 흉내 내지 않았고, 프롬프트에 게임·회사·작가 이름을 넣지 않았다.

## 시안별 설명과 약점

**1. 타이틀** — 마을 그림을 화면 가득 깔고, 위 가운데에 나무 명판 위의 "말빛 한울" 로고(한지빛 글자 → 아래쪽 연한 금빛, 먹갈색 윤곽 + 나무색 바깥 윤곽, 은은한 빛, 빛나는 말빛 주머니 장식)를 두었다. 아래 가운데에 굵은 버튼 둘: 초록 "처음부터"(선택 표시 잎 화살표), 나무색 "이어하기". 이름과 모습 고르기는 5번 화면으로 옮겼다.
- 약점: 배경이 원래 `title.webp`와 조금 다르다. 가운데에 집 하나가 새로 생기고 우물이 사라졌다. 실제로는 원래 그림 위에 로고와 버튼만 올리므로 문제가 되지 않는다. 로고 명판이 꽤 커서 하늘을 많이 가린다. 구현 때 로고 폭을 화면의 45% 안팎으로 줄인다.

**2. 탐험** — 베이지 여백을 없애고 맵을 화면 끝까지 채웠다. 위쪽에만 HUD를 띄웠다. 왼쪽 위는 주인공 초상 메달과 두루마리 할 일 표("● 우물에서 물 길어 오기"), 오른쪽 위는 "이 장의 낱말 0/5"와 빈 가방 3칸, 그 옆에 책 아이콘 "도감"(E)과 두루마리 아이콘 "할 일"(Q) 버튼이다. 소리·설정·지도·돈 같은 없는 기능의 아이콘은 넣지 않았다.
- 약점: 맵을 그림 모델이 다시 그려서 도트 세부가 실제 `map_ch1-1_saebyeokgol.png`와 조금 다르다. 실제로는 원래 맵을 쓴다. 초상 메달 속 얼굴이 도트가 아니라 SD 일러스트이다. 구현 때 `bust_hero_*_base.webp`의 얼굴을 잘라 쓴다. 지금 화면의 "방향키로 걸어 보세요" 첫 안내는 일부러 뺐다(처음 한 번만 뜨는 안내라서). 구현 때는 같은 나무 틀의 작은 명판으로 띄운다. HUD 띠가 1366×768에서 약 80px로 지금(48px)보다 두껍다.

**3. 대화** — 대사 상자는 화면 폭 전체이다. 조각한 나무 틀에 놋쇠 모서리 장식과 초록·파랑 보석 징을 달고, 안쪽은 한지색이다. 상자 왼쪽 위에는 말하는 인물의 대표색(쪽빛 `#3B5BA5`) 제비꼬리 리본 이름표 "하늘"을 붙였고, 오른쪽 아래에 놋쇠 ▼를 두었다. 두 인물은 같은 높이로 상자 위에 선다.
- 약점: 듣는 인물(할머니)이 어둡게 처리되지 않았다(아트 바이블 7절: 밝기 62%, 채도 70%). 이건 코드에서 이미 하는 일이라 시안에만 빠진 것이다. 상자 높이가 약 205px로 규칙(190px)보다 조금 크다. 대사 글자는 약 30px로 26px 규칙보다 크다.

**4. 보스 퀴즈 전투** — 세 층을 지켰다. 잿빛 무대 위 오른쪽에 몬스터 명판 "안개 덩이"와 HP 6칸(5칸 참, 1칸 점선), 묶음 바로 위 왼쪽에 "하늘"과 하트 5개가 있다. 아래에는 몬스터 쪽으로 꼬리가 난 말풍선 문제 상자(왼쪽 위 "안개 덩이" 표, 오른쪽 위 초록 "빈칸 채우기" 표)와 보기 카드 4장을 **틈 없이(약 12px)** 붙여 화면 아래에 붙였다. 보기마다 놋쇠 동전 번호 배지 1~4가 달려 있다.
- 약점: 문장의 큰따옴표가 빠졌다. 하트가 아트 바이블 다홍 `#E0584F`보다 붉다(`#E6312F` 안팎). 구현은 다홍으로 한다. 보기 카드는 기본 상태만 보이고 고름·정답·오답 상태는 그리지 않았다(아래 버튼 상태 표 참고). 말풍선 꼬리가 몬스터보다 왼쪽에서 올라간다. 뜻 고르기(2×2)와 문장 고르기(1열 4줄) 모양은 시안이 없다. 같은 카드 틀을 크기만 바꿔 쓴다.

**5. 모습 고르기** — 타이틀의 "처음부터" 다음 단계다. 위에 "모습 고르기" 명판, 그 아래 화면 위쪽 절반에 이름 칸("내 이름", "하늘", 도움말 한 줄)을 두었다. 태블릿 자판이 아래를 가리기 때문이다(7절). 가운데는 아치형 초상 카드 둘(고른 쪽은 밝은 놋쇠 테두리와 초록 체크 배지), 아래는 "뒤로"와 "시작하기"다.
- 약점: 카드에 글 이름표가 없다(7절: 그림 + 글 이름표). 구현 때 카드 아래에 작은 명판을 붙인다. 도움말 글자가 1366×768로 줄이면 약 16px라서 최소 18px 규칙보다 작다. 구현은 18px로 한다. 고르지 않은 남자 카드가 거의 어두워지지 않았다. 일러스트를 모델이 다시 그려서 남자아이 어깨끈 같은 세부가 실제 상반신 그림과 다르다. 실제로는 원래 `bust_hero_*_base.webp`를 쓴다. 고른 카드의 빛 번짐은 원칙 1(빛은 말에만)과 부딪친다. 빛 번짐 대신 체크 배지와 테두리 색으로만 보여 주기를 권한다.
- "이어하기"를 누르면 같은 화면에서 모습 카드를 빼고 이름 칸과 저장된 이름 버튼(48px 이상)만 보여 주는 방식을 권한다(이 경우는 시안 없음).

## UI 키트

### 틀(패널) 다섯 가지

| 이름 | 쓰는 곳 | 모양 |
|---|---|---|
| 큰 패널 `frame-panel` | 대사 상자, 이름 칸, 도감·할 일 창, 뜻풀이 카드 | 조각한 꿀빛 나무 테(두께 약 20px), 안쪽 놋쇠 선 1줄, 네 모서리 놋쇠 잎 장식 + 보석 징(초록·파랑), 안은 한지색 |
| 명판 `frame-plate` | HUD 낱말 막대, 몬스터 이름·HP, 주인공 하트, 화면 제목 | 큰 패널을 얇게(테 12px), 모서리 장식 작게 |
| 두루마리 `frame-scroll` | 할 일 표(HUD 왼쪽 위) | 한지 띠 + 오른쪽 끝에 말린 나무 축, 왼쪽은 초상 메달에 물림 |
| 말풍선 `frame-bubble` | 전투 문제 상자 | 큰 패널 + 따로 붙이는 꼬리 조각 |
| 카드 `frame-card` | 전투 보기, 모습 카드(위가 아치) | 나무 테 + 놋쇠 안쪽 선, 한지보다 조금 진한 크림 면 |

그 밖의 조각:
- 초상 메달: 지름 96px 나무 고리 + 놋쇠 테 + 아래 초록 보석. 안에는 상반신 그림의 얼굴을 둥글게 잘라 넣는다.
- 이름 리본: 제비꼬리 천 리본 + 놋쇠 핀 둘. 색은 말하는 인물의 대표색이다.
- 가방 칸: 들어간 짙은 나무 홈 + 한지색 점선. 물건이 들어오면 점선이 사라지고 32px 아이콘이 들어간다.
- 키 배지: 크림 바탕, 먹색 글자, 아래쪽 3px 진한 테두리(눌리는 자판 모양). 그림 없이 CSS로 만든다.
- 번호 동전: 지름 40px 놋쇠 동전 + 먹갈색 숫자.

### 버튼

| 종류 | 쓰는 곳 | 면 |
|---|---|---|
| 초록 주 버튼 | 처음부터, 시작하기, 확인 | 위 `#A6C94A` → 가운데 `#5FAE5A` → 아래 `#3E7A2C`, 아랫단 `#2F5A22` |
| 나무 버튼 | 이어하기, 뒤로, 다음 | 위 `#DE9735` → 아래 `#8D4A19`, 아랫단 `#5A2E0E` |
| 아이콘 버튼 | 도감 E, 할 일 Q | 72×80px 나무 틀, 아이콘 48px + 이름 20px + 오른쪽 위 키 배지 |

|---|---|
| 기본 | 위쪽 흰 윤기 띠, 아래 진한 단(4px), 오른쪽 아래 그림자 |

## 화면별 배치 (1366×768 기준, px)

**타이틀**
- 배경 `title.webp`를 `object-fit: cover`로 화면 가득.
- 로고: 가운데 위, 폭 600(화면의 약 45%), 위에서 40.
- 메뉴: 가운데, 버튼 340×76 둘, 사이 16, 첫 버튼 위끝이 y≈470. 키보드 위/아래와 엔터, 첫 초점은 "처음부터".

**모습 고르기**
- 제목 명판 360×64(위 24) → 이름 패널 680×130(위 104, 화면 위 절반 안) → 모습 카드 220×280 둘(사이 40) + 카드 아래 이름 명판 → 아래 버튼 "뒤로" 200×64, "시작하기" 260×72(아래 24).

**탐험**

## 웹앱에서 만드는 방법

### 1. 틀은 CSS `border-image` 9조각 PNG

틀을 하나의 큰 그림으로 붙이지 않는다. 모서리 4개, 변 4개, 가운데 1개로 나뉘는 **투명 PNG 한 장**을 만들고, CSS가 크기에 맞춰 늘린다. 글자는 늘 HTML이라 선명하다.

```css
.frame-panel {
  border: 24px solid transparent;               /* 화면에 보이는 테 두께 */
  border-image: url(/assets/ui/frame_panel.v1.png) 48 / 24px / 0 round;
  background: var(--parchment) padding-box;     /* 안쪽은 그림이 아니라 단색: 글자 대비를 보장 */
  border-radius: 14px;                          /* 배경이 테 밖으로 새지 않게 */
}
```

- 그림은 2배로 만든다(조각 48px → 화면 24px). @2x 화면에서도 또렷하다.
- 변은 `round`로 반복한다. AI 그림은 좌우가 안 맞으므로 **모서리 하나와 변 조각 하나만 고른 뒤 스크립트(PIL)로 뒤집어 붙여** 대칭 9조각 시트를 만든다(`tools/`에 작은 스크립트를 둔다).
- 만들기: `tools/kie-gen.py --resolution 1K --background transparent`(투명은 1K에서만 된다)로 틀을 그리거나, 2K 마젠타 배경으로 그린 뒤 sprite-gen cutout으로 지운다. 프롬프트에는 이 README의 색 hex와 "frame only, empty centre, no text"를 넣는다.
- 만들 PNG(예상 크기): `frame_panel`(192×192, ~40KB), `frame_plate`(128×96), `frame_scroll` + `scroll_rod`, `frame_card`, `frame_card_arch`, `bubble_tail`, `medallion`(192×192), `ribbon`(3조각: 왼꼬리·가운데·오른꼬리), `slot`, `btn_green`과 `btn_wood`(가로 3조각: 왼 끝·가운데·오른 끝). 합계 약 250KB.
- 버튼 상태는 PNG를 더 만들지 않는다. 올림은 `filter: brightness(1.08)`, 누름은 `transform: translateY(2px)`와 아랫단 조각을 숨긴 변형 한 장, 못 누름은 `filter: saturate(.4) opacity(.6)`. 초점은 `outline: 3px solid var(--hero); outline-offset: 2px`.
- 리본 색은 인물마다 PNG를 만들지 않는다. 리본 모양을 `mask-image`로 쓰고 `background-color: var(--speaker-color)`를 칠한 뒤, 접힘·그늘만 담은 회색 PNG를 `mix-blend-mode: multiply`로 덮는다.
- 키 배지, 번호 동전, HP 칸, 점선 빈칸, 하트 테두리는 CSS만으로 그린다(그라데이션, `box-shadow`, `border-style: dashed`).

### 2. 로고 PNG

- `assets/ui/logo_title.v1.webp`(투명, 약 1600×640, 150KB 이하). sprite-gen의 타이틀 로고 흐름(타이틀 화면에 로고를 그린 뒤 글자만 투명으로 떼어 냄)으로 만든다.
- 로고만 그림이 한글을 그리는 예외다. 글자가 맞는지 사람이 확인한다. 화면 읽기 프로그램을 위해 `<h1>`에 "말빛 한울"을 넣고 그림은 `alt=""` 장식으로 둔다.
- 로고가 깨지거나 승인이 안 되면 대체안: 주아로 쓴 SVG `<text>`에 `paint-order: stroke`로 먹갈색 6px + 나무색 12px 윤곽을 두르고, `linear-gradient` 채움, `filter: drop-shadow(0 0 12px #FFE7A3)` 빛을 준다. 글자는 늘 정확하다.
- 로고 옆 말빛 주머니만 은은하게 빛난다(2절 타이틀: 주머니 하나만 빛남). 로고 둘레 빛은 아주 약하게 둔다.

### 3. 아이콘 PNG

- 96×96 투명 PNG를 48px로 보인다: `icon_book`(도감), `icon_scroll`(할 일), `icon_arrow_leaf`(선택 화살표), `icon_next`(▼), `icon_check`, `icon_heart_full` / `icon_heart_empty` / `icon_heart_crack`.
- 7절 아이콘 규칙(둥근 선, 먹갈색 윤곽, 면 채움 하나)에 놋쇠·나무 색을 더한다. 글자 이름표는 늘 함께 붙인다.
- 가방 물건 아이콘은 이미 있는 도트 아이콘(`assets/pixel/icon_*.png`)을 그대로 쓴다.

### 4. 화면 가득 채우기 (베이지 여백 없애기)

- `body`의 한지색 여백과 가운데 정렬 카드를 없앤다. 모든 장면의 뿌리는 `position: fixed; inset: 0`이다.
- 타이틀·대화·전투 배경은 `object-fit: cover`로 화면을 덮는다. 아래 1/3이 단순한 그림이라 잘려도 괜찮다.
- 탐험 캔버스는 내부 크기를 화면 크기에 맞춘다. 아트 바이블 8절의 `f = min(1, 너비/1152, 높이/648)`는 그대로 쓰고, 캔버스 내부 크기를 `(화면 너비/f, 화면 높이/f)`로 잡는다. CSS 크기는 화면 전체로 한다. 그러면 1366×768에서는 1:1로 칸 28.5×16이 보이고(지금은 24×13.5), 작은 화면에서는 지금처럼 부드럽게 줄어든다. 늘 화면이 꽉 찬다.
- 카메라는 HUD 띠(위 88px)만큼 아래로 치우쳐 주인공이 HUD에 가리지 않게 한다. 맵이 화면보다 작은 곳에서는 맵 가장자리 색(짙은 숲 `#2F6B3A`)으로 채운다. 한지색 여백은 쓰지 않는다.
- HUD, 대사 상자, 전투 묶음은 모두 캔버스 위 HTML 층(`position: absolute`)이다. 7절 원칙(글자는 늘 패널 위)은 그대로다.

### 5. 내려받기 예산

틀 PNG 약 250KB + 로고 150KB + 아이콘 약 40KB + 주아 서브셋 증가 10KB = **약 450KB**. 처음 열 때 3MB 예산(8절) 안에 들어간다. 이름은 `assets/ui/` 아래 `frame_panel.v1.png`처럼 버전을 붙인다.
