# 1막 그림 적용 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 임시 단색 블록 대신 1막 「새벽골」의 실제 그림(도트 맵 2장, 도트 인물, 물건 아이콘, 일러스트 상반신·배경·전투 장면·몬스터·타이틀)을 만들어 게임에 넣고, 선생님이 직접 플레이해 볼 수 있는 주소를 만든다.

**Architecture:** 그림은 KIE.AI GPT Image 2.5(호출당 과금, `KIE_AI_API_KEY`)로 만든다. 도트 맵은 지금 맵 데이터(`data/acts/act1.js`의 32×24 격자)를 색 밑그림으로 그려 올린 뒤 image-to-image로 그리게 하고, 결과를 512×384 도트로 줄여 색표에 맞춘다. 그림 경로는 `data/assets.js` 한 곳에 모으고, 화면 코드는 그림이 있으면 그림을, 못 불러오면 지금의 임시 그림을 그린다(설계 9절). 생성 원본(2K PNG)은 저장소에 넣지 않고, 게임에 쓰는 결과물만 `assets/`에 넣는다.

**Tech Stack:** Python 3(Pillow, sprite-gen venv의 인터프리터), Node 22, KIE.AI API(파일 올리기 + `gpt-image-2-5-flare-text-to-image` / `-image-to-image`), sprite-gen `cutout`(마젠타 배경 지우기), Vercel(미리보기 배포).

**Spec:** `docs/superpowers/specs/2026-11-04-woorimal-rpg-design.md` 6절 · 아트 바이블 `design/art/art-bible.md`(1~9절 전부, 특히 5·6·8·9절) · 시안 `design/art/concepts/ch1/`(프롬프트와 미리보기)

**선행 조건:** `docs/superpowers/plans/2026-11-04-act1-playable.md`의 Task 1~15 완료(임시 그림으로 1막 끝까지 플레이 가능).

## Global Constraints

- **도트 세밀도(선생님 결정): 칸당 48도트.** 게임 칸·걷기 격자는 그대로이고 그림만 3배 촘촘하다. 맵 1536×1152 색표 PNG 64색 이하·투명 0/100%·700KB 이하, 인물 도트 48×96칸(그림은 48×72), 주인공 걷기 시트 144×384(3프레임 × 4방향, 줄 순서 아래·왼·오·위, 좌우 뒤집기 금지), 물건 아이콘 48×48, 캔버스 내부 1152×648(크롬북 1366×768에서 1:1), 대화·전투 배경과 타이틀 WebP 2560×1440 품질 85 700KB 이하, 상반신 WebP 투명 1080×1440 300KB 이하, 몬스터 WebP 투명 1440×1440 400KB 이하.
- 이름 규칙: `종류_장_이름_변형.확장자`, 소문자 로마자, 폴더 `assets/pixel/`, `assets/illust/`. 예: `map_ch1-1_saebyeokgol.png`, `npc_dodam.png`, `walk_hero_f.png`, `bust_dodam_laugh.webp`, `bg_ch1-1.webp`, `battle_hero_f.webp`, `monster_act1.webp`, `icon_water.png`.
- 아트 바이블 9절 프롬프트 규칙: 쓸 말(`detailed pixel art, 48 pixels per tile`, `top-down 3/4 view`, `limited palette`, `cozy fantasy village`, `light from upper left`, `soft cel shading`, `modern adventure outfit`, `child-friendly`, `faceless grey silhouette crowd`, `solid magenta background` 등)을 쓰고, 게임·작가 이름, `in the style of`, 전통 의상·초가·기와·한옥, 나라 이름을 옷·건물 설명에 붙이기, 선정·공포 표현은 쓰지 않는다.
- 대표색: 주인공 쪽빛 `#3B5BA5`, 도담 할머니 자주 `#8E4A7A`. 마을 사람과 소품에는 대표색 4가지를 쓰지 않는다. 주인공 말빛 주머니는 오른쪽 허리.
- 시안에서 지적된 것: 지붕이 초가처럼 나오지 않게("rounded slate or terracotta roof, not thatched"), 도트 인물은 2.5등신 16×24.
- 한 번 생성할 때마다 결과를 직접 보고 아트 바이블 8절 "그림마다 확인할 것" 목록으로 확인한다. 통과하지 못하면 프롬프트를 고쳐 다시 만든다(그림 하나당 최대 3번).
- 크레딧: 1막 전체 600크레딧 이하. 생성마다 `tools/kie-gen.py`가 남기는 보고서에 쓴 크레딧을 적고, 합계를 계획 끝에 기록한다.

## Review Focus

1. **맵 그림과 걷기 칸이 어긋남**: 그림에서는 길인데 못 걷거나, 집·나무 위를 걸어 다니면 학생이 바로 이상하다고 느낀다. → Task 3의 칸 겹쳐 보기 검사.
2. **그림을 못 불러올 때 멈춤**: 학교 필터나 느린 와이파이로 그림 하나가 안 오면 게임이 멈추면 안 된다(임시 그림으로 대신). → Task 6 화면 검사.
3. **용량**: 첫 화면 3MB, 장마다 6MB를 넘으면 25명이 동시에 열 때 느려진다. → Task 6 용량 검사.
4. **주인공 남·여 섞임**: 고른 모습과 다른 그림이 대화·전투에 나오면 안 된다. → Task 6 화면 검사.
5. **전투 화면 글자 가림**: 전투 무대 그림이 커져도 문제·보기 묶음은 가리지 않는다. → Task 6 스크린샷 확인.

### Task 1: 그림 도구

**Files:** Modify `tools/kie-gen.py`; Create `tools/layout-guide.mjs`, `tools/pixelize.py`, `tools/palette.json`, `tests/tools.test.mjs`

- `kie-gen.py`: `--ref PATH`(여러 번)를 받으면 파일을 `https://kieai.redpandaai.co/api/file-stream-upload`(multipart `file`, `uploadPath=woorimal`)에 올려 `data.downloadUrl`을 얻고, 모델을 `gpt-image-2-5-flare-image-to-image`로 바꿔 `input.input_urls`에 넣는다. `--ref`가 없으면 지금처럼 text-to-image.
- `layout-guide.mjs <act> <chapterId> <out.png>`: 맵 격자를 칸당 16px 색 밑그림(512×384)으로 그린다. 길 `#E8C88A`, 막힘 `#3E7A3A`, 물건 칸 `#8B5A2B`, 인물 칸 `#F2F2F2`, 안개 `#B9BBBE`, 몬스터 `#5E6266`, 시작 `#E8C88A`.
- `pixelize.py <in> <out> --size 512x384 [--palette tools/palette.json] [--max-colors 32]`: 최근접으로 줄인 뒤 색표에 가장 가까운 색으로 맞추고, 반투명은 0/255로 자른다.
- `palette.json`: 아트 바이블 4절 색과 음영 단계(약 30색).
- 검사: `layout-guide`가 512×384 PNG를 만들고 칸 색이 격자와 같은지, `pixelize`가 32색 이하·투명 0/255만 남기는지.
- Commit: `chore: image-to-image, layout guide and pixelize tools`
