# 2~5막·세계 지도·엔딩 그림 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 2~5막·세계 지도·엔딩의 `null` 그림 칸(맵 8, 인물 도트 19, 몬스터 도트 8, 아이콘 12, 상반신 39, 대화 배경 8, 전투 배경 4, 몬스터 일러스트 4, 엔딩 3, 세계 지도 1)을 1막과 같은 방법·화풍으로 채운다. 막마다 따로 배포할 수 있게 막 순서로 만든다.

**Architecture:** 1막 그림 계획(`docs/superpowers/plans/2026-11-04-act1-art.md`)의 방법을 그대로 쓴다. 생성은 KIE.AI GPT Image 2.5(`tools/kie-gen.py`, 1K 6·2K 10크레딧)로 한다. 도트 맵은 맵 데이터로 그린 색 밑그림을 image-to-image로 16px 맵으로 그리고, 그것을 `--ref`로 넣어 48px 맵을 다시 그린 뒤 `tools/pixelize.py`로 1536×1152·64색에 맞춘다. 인물·몬스터·아이콘은 마젠타 배경 시트를 자르고, 상반신·배경은 2K로 그려 WebP로 줄인다. 1막의 막 전용 스크립트(`design/art/act1/make_*.py`)는 기록으로 두고, 막 번호를 받는 공용 도구를 `tools/art/`에 새로 둔다. 크레딧은 `kie-gen.py`가 커밋되는 장부(`design/art/credits.tsv`)에 적고, 합계가 1,000을 넘을 생성은 시작 전에 막는다.

**Tech Stack:** Python 3(Pillow, numpy: `/root/.local/share/sprite-gen/.venv/bin/python -I`), Node 22(`node --test`, Playwright), KIE.AI(`gpt-image-2-5-flare-*`), sprite-gen `cutout`, GitHub Pages(push하면 `.github/workflows/pages.yml`이 `npm test` 뒤 배포).

**Spec:** `docs/superpowers/specs/2026-11-04-acts2-5-design.md` 7절(그림 목록·크레딧), 2절(표정 이름), 3-2절(HUD 동료 초상), 4절 막마다의 인물 표·맵·막 보스, 5절(세계 지도), 6절(엔딩). 아트 바이블 `design/art/art-bible.md` 1~9절 전부.

**선행 조건:** `docs/superpowers/plans/2026-11-04-acts2-5-build.md`의 모든 Task가 끝났다. `data/assets.js`에 2~5막·`worldmap`·`ending` 칸이 모두 `null`로 있고, `tests/e2e/capture-acts.mjs`가 있으며, `npm test`와 `npm run test:e2e`가 통과한다. `KIE_AI_API_KEY`는 환경 변수에만 있다(출력·파일에 쓰지 않는다). sprite-gen venv는 `tools/setup-art-tools.sh`로 설치한다.

- 대표색: 주인공 `#3B5BA5`, 도담 할머니 `#8E4A7A`, 해솔 `#F08A3C`, 나래 `#A9C9D6`(빛 모습 `#9FD3E8`). 이 색과 음영(Task 1의 `RESERVED`)은 주인이 아닌 인물·소품·맵·세계 지도에 쓰지 않는다.
- **원칙 1(빛은 말에서만)**: 말빛 금 `#F2C14E`·`#FFE7A3`, 빛 번짐, 반짝임, 역광은 `bust_narae_light`(얇은 금빛 테두리만, 빛 알갱이·번짐 없음), `icon_light-shard`(조각 자체의 색만, 둘레 빛 없음), `ending01`~`ending03`(새벽 금빛 역광)에만 쓴다. 5막 맵·배경·몬스터·잿빛 아이에는 광원이 없다: 가로등과 계단 등은 꺼져 있고, 금빛·불빛·별빛·달빛을 그리지 않으며, 맵 색표의 채도는 0.25 이하다. 3막 윤슬은 흰 1px 점뿐이고 볕뉘는 번짐 없는 평평한 볕 조각이다.
- **다시 쓰는 그림**: 주인공·도담 할머니·다온·1막 마을 사람은 새로 그리지 않는다. 해솔(3~5막)·나래(4·5막)·나무꾼·밤 장수 할머니·쉼터지기(5막)는 처음 나온 막의 그림을 같은 id로 그대로 쓴다. 5막에서 새로 그리는 인물은 잿빛 아이뿐이다.
- **주인공 모습 섞임 금지**: 엔딩 그림 세 장에는 주인공을 그리지 않는다(엔딩01·02는 사람 없는 장소, 엔딩03은 주인공 눈으로 본 일행). 세계 지도의 주인공은 고른 모습의 걷기 시트를 쓴다.
- 마을 사람은 도트·상반신 모두 머리 장식이 없다(아트 바이블 3·5절, 1막에서 텃밭·빵집 아저씨를 맨머리로 다시 그린 선례). 설계 인물 표의 모자(여울 둥근 챙 모자, 나룻배 사공 챙 넓은 모자, 가람 털모자, 나그네 할머니 챙 모자)는 그리지 않는다. 가람은 털모자 대신 턱까지 감은 두꺼운 목도리로 알아보게 한다.
- 맵 그림에는 인물, 안개 문(F), 몬스터(M·m), 빛을 그리지 않는다(코드가 위에 그린다). 안개는 4막 맵의 막힌 칸(`#`)에만 디더링으로 그리고, 걸을 수 있는 칸은 늘 평평한 길 색이다.
- 맵의 걸을 수 있는 칸은 데이터 맵과 맞아야 한다(`tools/map-fit.py score`, `tests/e2e/map-overlay.test.mjs`). 먼저 그림을 고치고(warp, 다시 생성), 데이터는 Task 1 Step 9의 규칙 안에서만 고친다.
- 생성마다 결과를 직접 보고(Read로 미리보기 PNG를 연다) 아트 바이블 8절 "그림마다 확인할 것"과 그 Task의 확인 목록으로 판단한다. 통과하지 못하면 프롬프트를 고쳐 다시 만든다. 그림 하나에 최대 3번.
- **크레딧 상한 1,000(이 계획 전체)**: 모든 `kie-gen.py` 호출에 `--ledger design/art/credits.tsv --task T<n> --cap 1000`을 붙인다. Task마다 아래 예산을 지킨다. 예산을 넘는 생성은 `1000 − 지금까지 쓴 것 − 남은 Task 예산 합` 안에서만 하고, 커밋 메시지에 까닭을 적는다.

- 커밋 전마다 `npm test`가 통과한다. 맵 묶음은 `node --test tests/e2e/map-overlay.test.mjs`도. 막의 마지막 Task 끝에 `npm run test:e2e` 전부. 배포는 막의 일러스트 Task 끝에 push 한 번(Pages 워크플로가 `npm test`를 다시 돌린다).

## Review Focus

1. **출구 길과 안개·잿빛 맵이 걷기 칸과 어긋남**: 출구 너머 `#` 칸에 길을 그리면 겹쳐 보기 검사가 "막혔는데 길처럼 보임"으로 떨어지고, 4막 안개·5막 잿빛 바닥은 길 색과 벽 색이 비슷해 학생이 갈 수 있는 곳을 못 읽는다. → Task 1(출구 통로 예외를 `score`와 e2e에 같은 규칙으로), Task 5·7(맵 색 검사와 직접 보기).
2. **표정이 바뀔 때 머리가 튐**: 해솔(3표정)·나래(4표정)는 대화 도중 그림이 자주 바뀐다. 머리·어깨가 몇 픽셀만 어긋나도 튀어 보인다. → Task 2 `tests/assets-align.test.mjs`(iou ≥ 0.95).
3. **잿빛이 잿빛 위에 묻힘**: 4막 안개 속 나래, 5막 잿빛 바닥 위의 꼬마 잿빛 그림자·잿빛 아이. → Task 1 `tests/assets-colors.test.mjs`(안개 회색은 4막 맵에만, 5막 맵은 잿빛 3단과 겹치는 색 없음), Task 5·7 스크린숏 확인.
4. **세로로 긴 5막 보스가 전투 화면을 깸**: 1440×2160 그림이 정사각 상자에서 작아지거나, 키운 상자가 보기를 가리거나, '나래' 문제의 숄 빛 자리가 아래 묶음 뒤로 숨는다. → Task 8 `tests/e2e/art-layout.test.mjs`.
5. **고른 모습과 다른 주인공**: 세계 지도의 주인공 도트, 엔딩 그림, 5-2에서 미리 받는 엔딩 그림에 다른 모습이 섞이면 안 된다. → Task 7 세계 지도 e2e, Task 8 예산 검사(5-2 + 엔딩 경로에 다른 모습 없음).

## 공통 절차

Task들은 아래 절차를 막·장 값만 바꿔 쓴다. `PY=/root/.local/share/sprite-gen/.venv/bin/python -I`, `R=design/art/act<n>/raw`, `K="--ledger design/art/credits.tsv --task T<Task 번호> --cap 1000"`.

**A. 맵 한 장(장 C, 이름 NAME)**
1. 밑그림: `node tools/layout-guide.mjs C $R/guide_C.png`. 막마다 한 번 화풍 참고: `$PY tools/pixelize.py assets/pixel/map_ch1-1_saebyeokgol.png $R/style16.png --size 512x384 --palette design/art/act1/map-palette.json --max-colors 64` 뒤 `$PY tools/map-fit.py scale $R/style16.png $R/style16x2.png 2`.
2. 16px 그리기: 프롬프트 `design/art/act<n>/prompts/map_C_16.txt`("첫 참고 그림은 색 밑그림: 모래색은 길, 흰 칸(사람 자리)과 회색 칸(안개 문·몬스터 자리)도 비어 있는 길로 그린다, 갈색 칸은 물건, 초록은 막힘. 배치를 그대로 지킨다. 둘째 참고 그림은 같은 세계의 화풍(칸당 16px)" + Task가 정한 장소 문장 + 1막 `map_1-1.txt`의 화풍·금지 문단). `python3 tools/kie-gen.py --prompt-file … --out $R/map_C_a1.png --aspect 4:3 --resolution 1K --ref $R/guide_C.png --ref $R/style16x2.png $K`.
3. 막의 첫 장이면 색표: `$PY tools/map-fit.py palette $R/map_C_a1.png --out design/art/act<n>/map-palette.json [Task가 정한 --allow-fog / --max-sat]`. 둘째 장은 같은 색표를 쓴다.
4. `$PY tools/pixelize.py $R/map_C_a1.png $R/map_C_a1_px.png --size 512x384 --palette design/art/act<n>/map-palette.json --max-colors 64` → `$PY tools/map-fit.py warp $R/map_C_a1_px.png C $R/map_C_16.png` → `$PY tools/map-fit.py score $R/map_C_16.png C` / Expected: `bad 0`. `$PY tools/map-fit.py overlay $R/map_C_16.png C $R/overlay_C_16.png`를 Read로 보고 Task의 확인 목록으로 판단한다. 안 되면 2부터 다시(최대 3번).
5. 48px 다시 그리기: `$PY tools/map-fit.py scale $R/map_C_16.png $R/map_C_ref48.png 4`, 프롬프트 `map_C_48.txt`(1막 `map_1-1.txt`를 틀로, 장소 문장만 바꿈). `kie-gen … --out $R/map_C_2k_a1.png --aspect 4:3 --resolution 2K --ref $R/map_C_ref48.png $K`.
6. `pixelize … --size 1536x1152 --palette design/art/act<n>/map-palette.json --max-colors 64` → `warp` → `score` / Expected: `bad 0` → `overlay … design/art/act<n>/overlay_C.png`(절반 크기)를 Read로 본다.
